## 1 引言

### 1.1 编写目的

本文档用于描述 SmartCalc-v2.0 智能计算器系统的系统需求，明确系统功能范围、运行环境、数据要求、性能需求、质量需求、开发约束和验收标准，为后续概要设计、详细设计、编码实现、测试用例设计、课程验收和维护提供依据。本文档按照课程系统需求分析文档模板组织，重点描述系统应具备的外部可见行为、输入输出规则、异常处理要求及可验收条件。

### 1.2 文档读者对象

项目开发人员：依据本文档理解系统功能边界、模块划分和实现约束。测试人员：依据需求编号、用例描述和验收标准编写测试用例。评审人员/ 指导老师：依据本文档评审项目需求完整性、可行性和一致性。维护人员：依据本文档理解系统的功能范围、数据流和约束条件。最终使用者代表：了解系统提供的表达式计算、变量计算和函数绘图能力。

### 1.3 项目背景

SmartCalc-v2.0 是一个基于 C++17 与 Qt 图形界面的桌面智能计算器。系统面向需要进行数学表达式计算和函数图像查看的用户，提供基础运算、扩展运算、数学函数、变量 x 计算、函数图像绘制、键盘输入、计算历史记录和图像导出等能力。系统采用模型 - 视图 - 控制器架构。视图层负责用户界面、按钮事件、表达式显示、变量输入和图像窗口；控制器层负责转发计算与绘图请求；模型层负责表达式解析、逆波兰表达式转换、数学求值和绘图坐标生成。系统为独立桌面程序，不依赖服务器、数据库或网络通信。新增计算历史记录和图像导出功能使用本地文件系统完成数据保存或文件输出。其主要外部依赖为 Qt Widgets 、 Qt PrintSupport 、 QCustomPlot 、 C++ 标准库、 GTest 、 CMake 和 Makefile 等开发测试工具。本项目委托单位为《软件工程方法与实践》课程组，开发单位为计算机学院课程项目小组，主管/ 指导部门为课程指导教师及学院相关教学管理单位。系统为独立桌面应用，与外部业务系统无数据交换关系，仅依赖本地操作系统、 Qt 运行环境和本地文件系统。

## 2 项目概述

### 2.1 系统目标

SmartCalc-v2.0 的目标是提供一个图形化、可交互、支持复杂数学表达式和函数图像绘制的桌面计算器。系统应满足以下总体目标：支持用户通过图形按钮输入完整数学表达式。支持加、减、乘、除、取模、幂、平方根等基础和扩展运算。支持 sin 、 cos 、 tan 、 asin 、 acos 、 atan 、 ln 、 log 等数学函数。支持变量 x ，并允许用户输入 x 的数值后进行表达式求值。支持基于表达式和 x 轴范围生成函数图像。支持输入合法性控制，避免形成明显无法解析的表达式。支持对无效数学结果显示 calculation error 。支持格式化显示计算结果，包括小数尾零清理和过长结果科学计数法显示。支持键盘输入数字、运算符、括号、变量 x 、退格、清空和等号计算等常用操作。支持保存、查看和清空最近计算历史记录，便于用户复查计算过程。支持将当前函数图像导出为 PNG 或 PDF 文件，便于用户提交报告或保存图像结果。

本系统可用于课程实验、数学学习和基础工程计算场景，帮助用户以图形化方式完成表达式计算和函数图像观察。通过在基础版本上增加键盘输入、历史记录和图像导出功能，系统提高了输入效率、结果复查能力和报告复用能力，具有较好的教学演示和课程实践价值。

### 2.3 运行环境

#### 2.3.1 客户端运行环境

操作系统：支持安装 Qt 的桌面操作系统。项目构建文件具备 macOS 和 Windows GUI 应用构建配置；课程验收环境以项目实际配置环境为准。

GUI 框架： Qt Widgets 。项目配置支持 Qt 6 或 Qt 5 的 Widgets 组件，并链接 Qt PrintSupport 。屏幕显示：主窗口固定尺寸约 285×650 ；图像窗口固定尺寸约 370×590 。输入设备：鼠标和键盘；主要交互方式为鼠标点击按钮与在 x 输入框输入数值。

#### 2.3.2 开发与构建环境

编程语言： C++17 。构建工具： CMake 3.5+ 、 Makefile 。编译器：支持 C++17 的 g++ 或 clang++ 。测试框架： GTest 。覆盖率工具： gcov 、 lcov 、 genhtml 。格式检查工具： clang-format ，采用 Google 代码风格。文档工具： Doxygen 风格文档。

#### 2.3.3 数据库与网络环境

本版本不使用数据库、服务器或网络通信。系统新增计算历史记录采用本地文件持久化，图像导出功能在用户选择路径后生成本地图像文件；因此系统无数据库部署要求、无后端服务器要求、无网络带宽要求。

### 2.4 假设和依赖

用户通过系统提供的图形界面输入表达式，不直接向模型层提交任意字符串。系统依赖 Qt 运行环境和 QCustomPlot 绘图库正常工作。系统依赖 C++ 标准数学库提供三角函数、对数、平方根和幂运算。模型层的输入前置条件为表达式已通过界面层合法性校验。图像绘制使用固定步长 0.1 对 x 范围采样；绘图响应时间与采样点数成正相关。本版本不维护用户账号、不读写业务数据库。计算历史记录以本地文件方式保存，用户可在系统内查看或清空。项目开发和验收依赖开发机安装 Qt 、 CMake 、 GTest 、 lcov 、 genhtml 、 clang-format 等工具。

### 3.3 功能描述

#### 3.3.1 表达式输入与编辑

表达式输入与编辑功能用于接收计算用户在主窗口中的输入操作，将按钮输入或键盘输入转换为系统可显示、可计算的表达式内容，并在输入过程中维护数字、小数点、运算符、括号、函数和变量等输入状态。该功能应保证用户在常规操作下形成符合计算规则的表达式，避免明显非法的输入序列进入后续计算流程。


<!-- source-page: 16 -->

##### 3.3.1.1 输入数字

**用例描述：** #SC-SRS-1.1.0

系统为计算用户提供数字输入功能。用户可通过数字按钮或键盘输入 0 ～ 9 ，系统在当前位置语法合法时将数字作为表达式 token 追加到当前表达式中，并同步更新显示文本和内部表达式。

**优先级：** 1

**前置条件：** 主窗口已打开，系统处于可接收输入状态。

**后置条件：** 显示区展示更新后的表达式，内部表达式与显示文本保持一致。

**参与者：** 计算用户。

**输入数据：** 数字 0 ～ 9 。

**输出数据：** 表达式显示文本、内部表达式文本。

**基本事件流：**

1. 用户点击数字按钮或按下数字键。

2. 系统判断当前位置是否允许输入数字。

3. 若输入位置合法，系统将数字追加到显示表达式和内部表达式。

4. 系统刷新主窗口显示区。

5. 系统更新当前输入状态，为后续继续输入数字、小数点、运算符或计算操作提供依据。

**异常/替代事件流：**

1. 若当前位置紧跟右括号或变量 x ，继续输入数字会造成隐式乘法歧义，系统应拒绝追加该数字。

2. 若当前输入会导致数字 token 格式非法，系统应保持原表达式不变。

##### 3.3.1.2 输入小数点

**用例描述：** #SC-SRS-1.2.0

系统允许计算用户在数字 token 中输入小数点，用于构成小数。系统应保证同一个数字 token 中最多只能包含一个小数点。

**优先级：** 1

**前置条件：** 当前位置处于数字输入状态，且当前数字 token 尚未包含小数点。

**后置条件：** 当前数字 token 追加小数点，显示文本和内部表达式同步更新。

**参与者：** 计算用户。

**输入数据：** 小数点“.”。

**输出数据：** 包含小数点的表达式。

**基本事件流：**

1. 用户点击小数点按钮或按下小数点键。

2. 系统检查当前输入位置是否属于数字 token 。

3. 系统检查当前数字 token 中是否已存在小数点。

4. 若检查通过，系统在当前数字 token 后追加小数点。

5. 系统刷新表达式显示并更新输入状态。

**异常/替代事件流：**

1. 若当前数字 token 已包含小数点，系统应拒绝输入第二个小数点。


<!-- source-page: 17 -->

2. 若当前位置不是数字输入状态，系统应忽略该小数点输入。

##### 3.3.1.3 输入科学计数法

**用例描述：** #SC-SRS-1.3.0

系统支持计算用户使用科学计数法输入数值。用户可在合法数字 token 后输入 e ，并继续输入指数符号或指数数字，系统在计算时应将完整科学计数法 token 作为一个数值处理。

**优先级：** 2

**前置条件：** 当前 token 为数字，且尚未包含科学计数法标记 e 。

**后置条件：** 表达式中追加 e ，系统允许用户继续输入指数部分。

**参与者：** 计算用户。

**输入数据：** e 、指数符号、指数数字。

**输出数据：** 科学计数法表达式。

**基本事件流：**

1. 用户先输入科学计数法的底数部分。

2. 用户点击 e 按钮或按下 e 键。

3. 系统检查当前位置是否允许输入科学计数法标记。

4. 若检查通过，系统追加 e ，并将当前 token 标记为科学计数法输入状态。

5. 用户继续输入指数符号或指数数字。

6. 系统在计算阶段将该完整 token 按数值进行解析。

**异常/替代事件流：**

1. 若当前位置不是数字 token ，系统应拒绝输入 e 。

2. 若当前数字 token 已包含 e ，系统应拒绝重复输入科学计数法标记。

3. 若指数部分格式非法，系统应在计算前拒绝表达式或在计算时返回错误状态。

##### 3.3.1.4 输入加减乘除

**用例描述：** #SC-SRS-1.4.0

系统为计算用户提供加、减、乘、除四类基础运算符输入功能。用户可通过界面按钮或键盘输入运算符，系统在语法合法时将其追加到表达式中，并按照内部计算规则进行统一表示。

**优先级：** 1

**前置条件：** 当前位置允许输入运算符；表达式起始位置仅允许一元正号或一元负号。

**后置条件：** 表达式追加对应运算符，输入状态切换为运算符输入状态。

**参与者：** 计算用户。

**输入数据：** + 、 - 、×、÷ 或键盘中的 + 、 - 、* 、/ 。

**输出数据：** 带运算符的表达式。

**基本事件流：**

1. 用户点击运算符按钮或按下运算符键。

2. 系统判断当前表达式位置是否允许输入该运算符。

3. 系统将界面显示运算符转换为内部可计算运算符。

4. 系统将运算符追加到表达式中。

5. 系统刷新显示文本并更新输入状态。


<!-- source-page: 18 -->

**异常/替代事件流：**

1. 若用户连续输入二元运算符，系统应拒绝追加第二个二元运算符。

2. 若表达式当前以小数点、科学计数法标记或其他非法结尾结束，系统应拒绝追加二元运算符。

3. 若用户在表达式起始位置输入 + 或 - ，系统将其作为一元正负号处理。

##### 3.3.1.5 输入取模运算

**用例描述：** #SC-SRS-1.5.0

系统支持取模运算输入。用户可在数字、变量或右括号等可作为左操作数的位置输入 mod ，系统在后续计算中按照取模规则处理该运算。

**优先级：** 2

**前置条件：** 当前表达式最后一个 token 可作为取模运算的左操作数。

**后置条件：** 表达式追加取模运算符，输入状态切换为运算符输入状态。

**参与者：** 计算用户。

**输入数据：** mod 按钮或对应键盘输入。

**输出数据：** 包含取模运算的表达式。

**基本事件流：**

1. 用户点击 mod 按钮或输入对应取模符号。

2. 系统判断当前位置是否允许输入取模运算符。

3. 若输入位置合法，系统追加取模运算符。

4. 系统刷新显示文本并更新输入状态。

5. 计算阶段系统按取模语义输出结果。

**异常/替代事件流：**

1. 若取模运算的除数为 0 ，系统应显示 calculation error 。

2. 若当前位置不能作为取模运算的左操作数，系统应拒绝输入。

**约束说明：** 本版本取模运算按照整数取模语义处理。

##### 3.3.1.6 输入幂运算

**用例描述：** #SC-SRS-1.6.0

系统支持幂运算输入。用户在输入底数后可使用 xʸ 功能输入指数表达式，系统应将底数和指数作为幂运算的两个操作数，并在计算阶段输出幂运算结果。

**优先级：** 2

**前置条件：** 当前表达式最后一个 token 可作为幂运算底数。

**后置条件：** 表达式追加幂运算结构，系统允许用户继续输入指数表达式。

**参与者：** 计算用户。

**输入数据：** xʸ 按钮或键盘幂运算符。

**输出数据：** 包含幂运算结构的表达式。

**基本事件流：**

1. 用户输入底数。

2. 用户点击 xʸ 按钮或输入幂运算符。

3. 系统判断当前表达式末尾是否可作为底数。


<!-- source-page: 19 -->

4. 若判断通过，系统追加幂运算结构。

5. 用户输入指数表达式并完成必要的括号闭合。

6. 计算阶段系统根据幂运算规则输出结果。

**异常/替代事件流：**

1. 若当前位置不能作为底数，系统应拒绝输入幂运算。

2. 若指数表达式不完整或非法，系统应拒绝计算或显示 calculation error 。

##### 3.3.1.7 输入平方根

**用例描述：** #SC-SRS-1.7.0

系统为计算用户提供平方根函数输入功能。用户可在表达式起始位置、运算符之后或左括号之后输入平方根函数，并在函数括号中填写被开方表达式。

**优先级：** 2

**前置条件：** 表达式为空，或当前位置位于运算符后、左括号后等可输入函数的位置。

**后置条件：** 表达式追加平方根函数结构，系统等待用户输入函数参数。

**参与者：** 计算用户。

**输入数据：** √ 按钮或对应键盘输入。

**输出数据：** 平方根表达式。

**基本事件流：**

1. 用户点击 √ 按钮或输入平方根函数。

2. 系统判断当前位置是否允许输入函数。

3. 若检查通过，系统追加平方根函数和左括号。

4. 用户输入被开方表达式并闭合括号。

5. 计算阶段系统输出平方根计算结果。

**异常/替代事件流：**

1. 若被开方表达式的结果小于 0 ，系统应显示 calculation error 。

2. 若当前位置不允许输入函数，系统应拒绝该输入。

##### 3.3.1.8 输入数学函数

**用例描述：** #SC-SRS-1.8.0

系统支持常用数学函数输入，包括 sin 、 cos 、 tan 、 asin 、 acos 、 atan 、 ln 和 log 。用户输入函数后，系统自动生成函数参数输入结构，并在计算阶段按照函数定义求值。

**优先级：** 1

**前置条件：** 表达式为空，或当前位置位于运算符后、左括号后等可输入函数的位置。

**后置条件：** 表达式追加函数名和左括号，系统等待用户输入函数参数。

**参与者：** 计算用户。

**输入数据：** sin 、 cos 、 tan 、 asin 、 acos 、 atan 、 ln 、 log 按钮或对应键盘输入。

**输出数据：** 包含数学函数的表达式。

**基本事件流：**

1. 用户点击函数按钮或输入函数快捷形式。

2. 系统判断当前位置是否允许输入函数。


<!-- source-page: 20 -->

3. 若检查通过，系统追加函数名和左括号。

4. 用户输入函数参数并闭合括号。

5. 系统在计算阶段根据函数类型和参数值输出结果。

**异常/替代事件流：**

1. 若函数参数超出定义域，系统应显示 calculation error 。

2. 若当前位置不允许输入函数，系统应拒绝该输入。

**约束说明：** 三角函数和反三角函数按照弧度制处理； ln 表示自然对数， log 表示常用对数。

##### 3.3.1.9 输入括号

**用例描述：** #SC-SRS-1.9.0

系统支持左括号和右括号输入，用于改变表达式运算优先级或填写函数参数。系统应维护括号配对状态，防止用户形成明显不平衡的括号结构。

**优先级：** 1

**前置条件：** 左括号处于可输入位置；右括号仅在存在未闭合左括号且当前 token 可作为表达式结尾

时输入。

**后置条件：** 表达式追加括号，括号状态同步更新。

**参与者：** 计算用户。

**输入数据：** 左括号“(”、右括号“)”。

**输出数据：** 带括号的表达式。

**基本事件流：**

1. 用户点击或输入左括号。

2. 系统判断当前位置是否允许输入左括号。

3. 系统追加左括号并更新未闭合括号数量。

4. 用户输入括号内表达式。

5. 用户点击或输入右括号。

6. 系统确认存在未闭合左括号，且当前 token 可作为表达式结尾。

7. 系统追加右括号并刷新显示。

**异常/替代事件流：**

1. 若不存在可匹配的左括号，系统应拒绝输入右括号。

3. 系统将显示区恢复为 0 。

4. 系统清空 x 输入框。

##### 3.3.1.11 退格删除

**用例描述：** #SC-SRS-1.11.0

系统允许计算用户删除最近一次输入的字符或完整 token 。退格删除后，系统应根据剩余表达式重新判断输入状态，保证用户能够继续编辑当前表达式。

**优先级：** 1

**前置条件：** 当前表达式非空。

**后置条件：** 最近输入的字符或 token 被删除，显示文本和内部表达式同步更新。

**参与者：** 计算用户。

**基本事件流：**

1. 用户点击退格按钮或按下 Backspace 键。

2. 系统识别最近输入内容的类型。

3. 若最近输入为普通数字或符号，系统删除对应字符。

4. 若最近输入为函数、平方根、幂运算结构等复合 token ，系统删除对应完整 token 或恢复到合理编辑状态。

5. 系统刷新显示文本。

6. 系统根据删除后的表达式重新计算输入状态。

7. 若表达式被删除为空，系统恢复初始显示状态。

**异常/替代事件流：**

1. 若表达式为空时触发退格，系统保持初始状态且不报错。

##### 3.3.2.1 表达式格式化

**用例描述：** #SC-SRS-2.1.0

系统在执行计算或绘图前，应将用户界面中的表达式转换为模型层可识别的内部表达式。格式化过程包括函数名转换、显示符号转换和表达式 token 标准化。

**优先级：** 1

**前置条件：** 用户触发计算或绘图，当前表达式已通过界面层合法性检查。

**后置条件：** 系统生成可提交给控制器和模型层处理的内部表达式。

**参与者：** 计算用户、系统。

**输入数据：** 界面表达式。

**输出数据：** 内部表达式。

**基本事件流：**

1. 用户触发计算或绘图操作。

2. 系统读取当前显示表达式和内部表达式。

3. 系统将界面函数名、数学符号和显示字符转换为计算模块可识别的 token 。

4. 系统生成内部表达式。

5. 系统将内部表达式和必要参数提交给控制器。

**异常/替代事件流：**

1. 若表达式为空或结构非法，系统应拒绝进入计算流程或给出错误提示。

##### 3.3.2.2 中缀转逆波兰表达式

**用例描述：** #SC-SRS-2.2.0

系统应将内部中缀表达式转换为逆波兰表达式序列，以便后续使用栈式求值方法完成计算。转换过程应遵守运算符优先级和括号匹配规则。

**优先级：** 1

**前置条件：** 系统已获得内部表达式。

**后置条件：** 生成逆波兰表达式 token 序列。

**参与者：** 系统。

**输入数据：** 内部表达式。

**输出数据：** RPN 词法单元序列。

**基本事件流：**

1. 系统从左到右扫描内部表达式。

2. 系统将数字、变量和科学计数法 token 直接加入输出序列。

3. 系统将左括号压入运算符栈。

4. 系统遇到右括号时，将运算符出栈直到匹配左括号。

5. 系统根据运算符优先级和结合规则处理运算符入栈与出栈。

6. 扫描完成后，系统将运算符栈中剩余 token 加入输出序列。

7. 系统返回 RPN 序列。

**异常/替代事件流：**


<!-- source-page: 24 -->

1. 若括号不匹配或表达式结构非法，系统应返回错误状态，或由界面层提前阻止该表达式进入计算流程。

##### 3.3.2.3 栈式求值

**用例描述：** #SC-SRS-2.3.0

系统应按照逆波兰表达式序列执行栈式求值。求值过程中，系统依次读取 token ，遇到操作数时入栈，遇到运算符或函数时弹出所需操作数并计算，最终得到表达式结果。

**优先级：** 1

**前置条件：** RPN 序列已生成。

**后置条件：** 系统返回表达式计算结果或错误状态。

**参与者：** 系统。

**输入数据：** RPN 序列、 x 值。

**输出数据：** long double 计算结果或错误状态。

**基本事件流：**

1. 系统初始化操作数栈。

2. 系统依次遍历 RPN 序列。

3. 遇到数字 token 时，系统将对应数值压入栈。

4. 遇到变量 x 时，系统将当前 x 输入值压入栈。

5. 遇到运算符或函数 token 时，系统弹出所需操作数并执行对应计算。

6. 系统将单步计算结果重新压入栈。

7. 遍历结束后，系统将栈顶元素作为最终计算结果。

8. 系统将计算结果返回给控制器。

**异常/替代事件流：**

1. 若数值转换越界，系统应返回错误状态。

2. 若运算产生 NAN 或 INF ，系统应将结果交由界面层显示为 calculation error 。

##### 3.3.2.4 基础运算求值

**用例描述：** #SC-SRS-2.4.0

系统应支持加、减、乘、除和取模等基础运算，并按照表达式中的运算优先级和括号结构输出正确结果。

**优先级：** 1

**前置条件：** 表达式中包含基础运算符，且表达式结构合法。

**后置条件：** 系统返回基础运算结果或错误状态。

**参与者：** 计算用户、系统。

**输入数据：** 基础运算表达式。

**输出数据：** 计算结果。

**基本事件流：**

1. 用户输入包含基础运算符的表达式。

2. 系统格式化表达式并进行 RPN 转换。

3. 系统按照 RPN 序列执行基础运算。


<!-- source-page: 25 -->

4. 系统将计算结果返回界面层。

5. 界面层显示结果或错误提示。

**异常/替代事件流：**

1. 除数为 0 或取模除数为 0 时，系统应显示 calculation error 。

2. 表达式结构非法时，系统应拒绝计算或显示错误提示。

##### 3.3.2.5 高级函数求值

**用例描述：** #SC-SRS-2.5.0

系统应支持幂、平方根、三角函数、反三角函数、自然对数和常用对数等高级数学计算，并在函数参数合法时返回对应结果。

**优先级：** 1

**前置条件：** 表达式中包含高级函数或扩展运算，且表达式结构合法。

**后置条件：** 系统返回高级函数计算结果或错误状态。

**参与者：** 计算用户、系统。

**输入数据：** 高级函数表达式。

**输出数据：** 计算结果。

**基本事件流：**

1. 用户输入包含高级函数或扩展运算的表达式。

2. 系统将界面函数名转换为内部 token 。

3. 系统根据表达式结构完成 RPN 转换。

4. 系统根据函数类型和参数执行数学求值。

5. 系统返回计算结果。

6. 界面层格式化并显示结果。

**异常/替代事件流：**

1. 当函数参数超出定义域时，系统应显示 calculation error 。

2. 当计算结果溢出或无法表示时，系统应显示 calculation error 。

**约束说明：** ln 表示自然对数， log 表示常用对数；三角函数和反三角函数采用弧度制。

##### 3.3.2.6 结果格式化显示

**用例描述：** #SC-SRS-2.6.0

系统应将模型层返回的计算结果转换为适合主窗口显示的文本。对于有效数值，系统应按整数、小数或科学计数法格式显示；对于无效结果，系统应显示 calculation error 。

**优先级：** 1

**前置条件：** 计算结果已返回界面层。

**参与者：** 系统。

**输入数据：** long double 计算结果。

**输出数据：** 显示文本。

**基本事件流：**

1. 系统接收模型层返回的计算结果。

2. 系统判断结果是否为 NAN 或 INF 。

3. 若结果无效，系统显示 calculation error 。

4. 若结果为整数，系统以整数形式显示。

##### 3.3.3.1 输入变量 x 值

**用例描述：** #SC-SRS-3.1.0

系统应提供变量 x 的输入区域，允许计算用户输入指定范围内的数值。系统在计算含 x 表达式时读取该数值，并将其作为变量 x 的实际取值。

**优先级：** 1

**前置条件：** 主窗口已打开。

**后置条件：** x 输入框保存合法数值文本。

**参与者：** 计算用户。

**输入数据：** x 值文本。

**输出数据：** double 或 long double 类型数值。

**基本事件流：**

##### 3.3.3.2 表达式中插入 x

**参与者：** 计算用户。

**输出数据：** 包含变量 x 的表达式。

**基本事件流：**

2. 系统判断当前位置是否允许插入变量。

3. 若检查通过，系统在当前表达式中追加 x 。

4. 系统刷新显示文本。

5. 系统更新输入状态。

**异常/替代事件流：**

1. 若变量 x 紧跟数字、右括号或另一个 x 会造成语法歧义，系统应拒绝追加。

##### 3.3.3.3 使用 x 值计算表达式

##### 3.3.4.1 打开图像窗口

**用例描述：** #SC-SRS-4.1.0

系统允许计算用户通过绘图入口打开函数图像窗口。若图像窗口已存在，系统应激活已有窗口；若窗口不存在，系统应创建并显示新的图像窗口。

**优先级：** 2

**前置条件：** 主窗口已打开。

**后置条件：** 图像窗口显示或被激活。

**参与者：** 计算用户。

4. 若图像窗口已存在，系统将其激活并置于可见状态。

**异常/替代事件流：**

##### 3.3.4.2 设置绘图范围

**用例描述：** #SC-SRS-4.2.0

系统应允许计算用户在图像窗口中设置 x 轴和 y 轴的显示范围。系统使用 x 轴范围生成采样点，并使用 x/y 轴范围控制图像显示区域。

**优先级：** 2

**前置条件：** 图像窗口已打开。

**后置条件：** 绘图范围被用于坐标生成和坐标轴显示。

**参与者：** 计算用户。

**输入数据：** x_min 、 x_max 、 y_min 、 y_max 。

**输出数据：** 绘图范围参数。

**基本事件流：**

1. 用户在图像窗口中设置坐标范围。

2. 系统读取 x 轴最小值和最大值。

3. 系统读取 y 轴最小值和最大值。

4. 系统根据 x 轴范围生成采样点。

5. 系统根据 x/y 轴范围设置图像显示区域。

**异常/替代事件流：**

1. 若 x_max 小于或等于 x_min ，系统不绘制有效曲线并给出相应处理。

2. 若范围值超出控件允许范围，系统应拒绝输入或恢复合法值。

**约束说明：** 坐标范围控件允许值为 -1000000 到 1000000 ；默认 x 范围为 -10 到 10 ，默认 y 范围为 -

5 到 5 。

##### 3.3.4.3 生成绘图坐标

**用例描述：** #SC-SRS-4.3.0

系统应根据当前表达式和 x 轴范围生成绘图所需的坐标序列。系统以固定步长对 x 范围进行采样，并对每个采样点计算对应 y 值。

**优先级：** 2

**前置条件：** 表达式合法，且系统可以读取 x 轴范围。

**后置条件：** 系统生成 x 、 y 坐标序列。

**参与者：** 系统。

**输入数据：** 表达式、 x_min 、 x_max 。

**输出数据：** 坐标序列。

**基本事件流：**

1. 系统读取当前表达式和 x 轴范围。

2. 系统从 x_min 开始按固定步长生成 x 采样点。

3. 系统对每个 x 采样点计算对应 y 值。

4. 系统将 x 值和 y 值分别加入坐标序列。

5. 采样结束后，系统将坐标序列返回给图像窗口。

**异常/替代事件流：**

1. 若表达式非法，系统不生成有效坐标序列。

2. 若某些采样点产生无效 y 值，系统应按图像绘制规则处理该点或跳过该点。

**约束说明：** 采样步长固定为 0.1 ，采样点数约为 (x_max - x_min) / 0.1 。

##### 3.3.4.4 绘制函数图像

**用例描述：** #SC-SRS-4.4.0

系统应将绘图坐标序列显示为函数曲线。用户可在图像窗口中观察函数趋势，并通过拖拽和缩放调整观察区域。

**优先级：** 2

**前置条件：** 坐标序列已生成。

**后置条件：** 图像窗口显示函数曲线。

**参与者：** 计算用户、系统。

**输入数据：** 坐标序列、 x/y 轴范围。

**输出数据：** 函数图像。

**基本事件流：**

1. 系统清除旧图像或旧曲线数据。

2. 系统将坐标序列传递给绘图组件。

3. 系统设置 x 轴和 y 轴显示范围。

4. 系统绘制函数曲线。

5. 系统刷新图像窗口。


<!-- source-page: 31 -->

6. 用户可对图像进行拖拽和缩放。

**异常/替代事件流：**

1. 若当前表达式为空，系统清空图像区域。

2. 若当前表达式结构非法，系统显示 invalid input 并清除无效曲线。

#### 3.3.5 界面显示与错误处理

界面显示与错误处理功能用于保证主窗口和图像窗口能够正确展示表达式、结果、错误提示和当前状态。系统应在无效输入、无效计算结果、绘图失败和导出失败等情况下给出明确反馈，避免程序崩溃或界面状态异常。

##### 3.3.5.1 显示表达式与结果

**用例描述：** #SC-SRS-5.1.0

系统应在主窗口中显示用户当前输入的表达式、计算结果或错误提示。显示内容应与系统内部表达式和当前计算状态保持一致。

**优先级：** 1

**前置条件：** 用户执行输入、计算或清空等操作。

**后置条件：** 主窗口显示区与系统当前状态一致。

**参与者：** 计算用户、系统。

**输入数据：** 用户输入、计算结果、错误状态。

**输出数据：** 显示文本。

**基本事件流：**

1. 用户执行输入操作。

2. 系统根据输入规则更新表达式显示。

3. 用户触发表达式计算。

4. 系统执行计算并返回结果。

5. 系统格式化结果。

6. 系统在显示区展示结果或 calculation error 。

**异常/替代事件流：**

1. 若输入被系统拒绝，显示区保持原状态。

2. 若计算结果无效，显示区显示 calculation error 。

##### 3.3.5.2 错误处理

**用例描述：** #SC-SRS-5.2.0

系统应对非法输入、无定义数学结果、越界数值、无效绘图状态和导出异常进行处理。错误处理应保证系统不崩溃，并向用户提供可理解的反馈。

**优先级：** 1

**前置条件：** 输入、计算、绘图或导出过程中出现非法状态。

**后置条件：** 系统保持可继续使用状态，并显示错误提示或拒绝非法操作。

**参与者：** 计算用户、系统。

**输入数据：** 非法输入、无定义数学表达式、越界数字、无效图像状态、不可写文件路径。

**输出数据：** 错误提示或拒绝输入结果。


<!-- source-page: 32 -->

**基本事件流：**

1. 系统通过输入规则避免形成明显非法表达式。

2. 若计算结果为 NAN 或 INF ，系统显示 calculation error 。

3. 若绘图表达式结构非法，图像窗口显示 invalid input 。

4. 若导出图像失败，系统显示导出失败提示。

5. 用户可通过 C 或清空操作恢复到可输入状态。

**异常/替代事件流：**

1. 错误提示显示后，系统不得丢失可恢复的表达式状态，除非用户主动执行清空操作。

2. 历史记录写入失败不得影响本次计算结果显示。

3. 图像导出失败不得关闭图像窗口或清除当前有效曲线。

#### 3.3.6 键盘输入支持

键盘输入支持功能允许计算用户在不使用鼠标点击按钮的情况下，通过键盘完成常用表达式输入和快捷操作。键盘输入应与按钮输入遵循相同的表达式合法性规则，不能绕过系统的输入限制。


<!-- source-page: 33 -->

##### 3.3.6.1 键盘表达式输入

**用例描述：** #SC-SRS-6.1.0

系统应支持用户通过键盘输入数字、运算符、小数点、科学计数法标记、括号和变量 x 。系统应将键盘输入映射为与按钮输入一致的表达式 token ，并按相同规则更新表达式。

**优先级：** 2

**前置条件：** 主窗口处于激活状态，输入焦点位于主窗口或表达式输入区域。

**后置条件：** 显示表达式和内部表达式同步更新。

**参与者：** 计算用户。

**输入数据：** 键盘字符 0 ～ 9、 + 、 - 、* 、/ 、% 、^ 、.、 e 、 x 、 (、) 。

**输出数据：** 更新后的表达式。

**基本事件流：**

1. 用户按下键盘字符。

2. 系统捕获键盘事件。

3. 系统识别按键对应的表达式 token 。

4. 系统按照按钮输入相同的规则检查当前位置是否合法。

5. 若输入合法，系统追加对应 token 并刷新显示。

6. 若输入非法，系统保持当前表达式不变。

**异常/替代事件流：**

1. 无法识别的键盘字符不应影响当前表达式。

2. 键盘输入形成的小数点、括号、运算符和变量结构应与按钮输入规则保持一致。

##### 3.3.6.2 键盘快捷操作

**用例描述：** #SC-SRS-6.2.0

系统应支持常用键盘快捷操作，使用户能够通过键盘触发表达式计算、退格删除和清空表达式等操作。

**优先级：** 2

**前置条件：** 主窗口处于激活状态。

**后置条件：** 系统执行对应快捷操作并刷新界面状态。

**参与者：** 计算用户。

**输入数据：** Enter 、 Return 、 Backspace 、 Esc 、 Delete 等快捷键。

**输出数据：** 计算结果、更新后的表达式或初始状态。

**基本事件流：**

1. 用户按下快捷键。

2. 系统识别快捷键类型。

3. 若用户按下 Enter 或 Return ，系统触发表达式计算。

4. 若用户按下 Backspace ，系统执行退格删除。

5. 若用户按下 Esc 或 Delete ，系统清空表达式并恢复初始状态。

6. 系统刷新主窗口显示。

**异常/替代事件流：**


<!-- source-page: 34 -->

1. 表达式为空时按 Backspace ，系统不报错且保持初始状态。

2. 表达式非法时按 Enter ，系统应拒绝计算或显示 calculation error 。

3. 当输入焦点位于不应触发表达式输入的控件中时，系统应避免错误处理快捷键。

#### 3.3.7 计算历史记录管理

计算历史记录管理功能用于保存用户成功计算的表达式、 x 值、结果和计算时间，并允许用户查看、复用和清空历史记录。该功能应仅保存有效计算结果，不保存 calculation error 等失败结果。

##### 3.3.7.1 保存计算历史记录

**用例描述：** #SC-SRS-7.1.0

系统应在用户完成一次有效计算后自动生成历史记录条目，并将该条目保存到本地历史记录存储中。历史记录用于用户后续查看和复用计算内容。

**优先级：** 2

**前置条件：** 用户完成一次有效计算，计算结果不是 calculation error 。

**后置条件：** 系统新增一条历史记录，并刷新历史记录区域。

**参与者：** 计算用户、系统。

**输入数据：** 表达式、 x 值、计算结果、计算时间。

**输出数据：** 历史记录条目。

**基本事件流：**

1. 用户输入表达式并触发计算。

2. 系统完成计算并得到有效结果。

3. 系统生成历史记录条目，记录表达式、 x 值、结果和时间。

4. 系统将记录写入本地历史记录文件或本地历史存储。

5. 系统刷新历史记录区域，显示最新记录。

**异常/替代事件流：**

1. 计算失败、表达式非法或结果为 NAN/INF 时，系统不保存历史记录。

2. 若历史记录数量超过上限，系统应删除最早记录以保持容量限制。

3. 若历史记录写入失败，系统应保留本次计算结果显示，并向用户提示历史保存失败或静默跳过保存。

**约束说明：** 历史记录默认保存最近 100 条。

##### 3.3.7.2 查看历史记录

**用例描述：** #SC-SRS-7.2.0

系统应允许用户查看最近的计算历史记录。历史记录应按时间倒序展示，用户可选择某条记录并将其中的表达式和 x 值载入主计算界面。

**优先级：** 2

**前置条件：** 历史记录区域可访问。

**后置条件：** 历史记录列表显示最近计算记录；用户可复用指定记录。

**参与者：** 计算用户。

**输入数据：** 历史记录入口、历史记录选择操作。

**输出数据：** 历史记录列表、被载入的表达式和 x 值。


<!-- source-page: 35 -->

**基本事件流：**

1. 用户打开历史记录区域。

2. 系统读取本地历史记录。

3. 系统按时间倒序显示历史记录。

4. 用户选择某条历史记录。

5. 系统将该记录中的表达式和 x 值载入主窗口。

6. 用户可基于载入内容继续编辑、计算或绘图。

**异常/替代事件流：**

1. 若不存在历史记录，系统应显示空状态提示。

2. 若历史记录文件读取失败，系统应提示读取失败，并保持主计算功能可用。

##### 3.3.7.3 清空历史记录

**用例描述：** #SC-SRS-7.3.0

系统应允许用户清空本地保存的计算历史记录。清空后，历史记录区域应显示为空状态，且后续新计算可继续生成新的历史记录。

**优先级：** 3

**前置条件：** 历史记录区域可访问。

**后置条件：** 本地历史记录和界面历史列表被清空。

**参与者：** 计算用户。

**输入数据：** 清空历史按钮或菜单命令。

**输出数据：** 空历史记录状态。

**基本事件流：**

1. 用户触发清空历史记录操作。

2. 系统执行清空本地历史记录的操作。

3. 系统刷新历史记录区域。

4. 历史记录区域显示为空状态。

**异常/替代事件流：**

1. 若历史记录文件删除或写入失败，系统应提示清空失败，并保持原记录不变。

2. 若当前没有历史记录，用户执行清空操作时，系统应保持空状态且不报错。

#### 3.3.8 函数图像导出

函数图像导出功能用于将当前绘图窗口中的有效函数图像保存为本地 PNG 或 PDF 文件，便于用户在实验报告、课程作业或文档中复用图像结果。系统应在导出前检查当前图像状态和目标路径，确保导出失败不会影响当前图像显示。

##### 3.3.8.1 导出函数图像

**用例描述：** #SC-SRS-8.1.0

系统应允许用户将当前绘图窗口中的有效函数图像导出为 PNG 或 PDF 文件。用户选择保存路径和文件格式后，系统将当前图像内容写入指定文件。

**优先级：** 2

**前置条件：** 图像窗口已打开，且当前存在有效函数曲线。

**后置条件：** 系统在用户指定路径生成 PNG 或 PDF 文件。

**参与者：** 计算用户。

**输入数据：** 导出命令、文件路径、导出格式。

**输出数据：** PNG/PDF 文件、导出结果提示。

**基本事件流：**

1. 用户在图像窗口点击导出按钮或选择导出菜单项。

2. 系统检查当前是否存在有效函数图像。

3. 系统弹出文件保存对话框。

4. 用户选择导出路径和导出格式。

5. 系统将当前图像内容写入指定文件。

6. 系统提示导出成功或在状态区域显示成功信息。

**异常/替代事件流：**

1. 用户取消保存对话框时，系统不生成文件且不报错。

2. 若导出过程中写入失败，系统应提示导出失败，并保持当前图像窗口状态不变。

##### 3.3.8.2 图像导出错误处理

**用例描述：** #SC-SRS-8.2.0

系统应处理图像导出过程中的异常情况，包括无有效图像、导出路径不可写、文件格式不支持或文件写入失败等。导出失败时，系统应给出明确提示，并保持当前图像显示不受影响。

**优先级：** 2

**前置条件：** 用户触发图像导出操作。

**后置条件：** 若导出失败，系统给出失败提示，不生成不完整文件，不清除当前曲线。

**参与者：** 计算用户、系统。

**输入数据：** 导出命令、导出路径、导出格式、当前图像状态。

**输出数据：** 导出失败提示或拒绝导出结果。

**基本事件流：**

1. 用户触发图像导出操作。

2. 系统检查当前是否存在有效图像。

3. 系统检查用户选择的文件格式是否受支持。

4. 系统检查目标路径是否可写。

5. 若全部检查通过，系统执行图像导出。

6. 若任一检查失败，系统显示导出失败提示。

**异常/替代事件流：**


<!-- source-page: 38 -->

1. 当前表达式非法、图像为空或目标路径不可写时，系统不得生成不完整文件。

2. 导出失败不得导致图像窗口关闭、曲线丢失或主窗口状态异常。

## 5 性能需求

### 5.1 数据精确度

核心计算模块使用 long double （至少 15 ～ 17 位有效十进制数字）保存和计算结果。课程验收测试中的浮点比较误差采用 1e-7 。界面显示小数结果时保留约 7 位小数，并去除尾随 0 。显示文本长度大于等于 21 时，系统采用科学计数法显示。 x 输入框最多允许 6 位小数。图像采样步长固定为 0.1 ，图像曲线为离散采样点连线，不作为高精度数值分析输出。键盘输入响应时间应与按钮输入保持一致，按键后 0.1 秒内更新显示文本。打开历史记录区域并加载最近 100 条记录时，界面响应时间应不超过 0.5 秒。默认绘图规模下，图像导出为 PNG 或 PDF 的响应时间应不超过 2 秒。

### 5.2 时间特性

在表达式长度不超过 255 个字符且不触发大量嵌套函数的验收输入规模下，点击“=”后 0.5 秒内显示计算结果。表达式解析与计算复杂度近似与 token 数量线性相关。默认绘图范围 -10 到 10 时约生成 200 个采样点，图像刷新应在 1 秒内完成。绘图响应时间与采样点数相关，采样点数约为 (x_max - x_min) / 0.1 。

### 5.3 适应性

系统应能在安装 Qt 基础运行时库的桌面环境中构建运行。项目优先以 Qt 6 运行时库验收，构建配置保留 Qt 5/Qt 6 兼容能力。系统界面为固定尺寸，不要求响应式适配；在 1366×768 及以上桌面分辨率下，主窗口和图像窗口应完整显示。系统模型层与视图层通过控制器隔离，计算核心可在不启动 GUI 的情况下执行单元测试。历史记录文件应控制在轻量级文本或结构化文件规模内，默认 100 条记录不应造成明显存储压力。图像导出仅在用户触发导出时写入本地文件，不应在普通绘图过程中持续写入磁盘。

### 5.4 资源利用率

默认输入规模下，普通表达式计算不应造成界面超过 0.5 秒的阻塞。绘图内存使用量与采样点数线性相关，每个采样点保存 x/y 两个 double （至少 15 ～ 17 位有效十进制数字）数值。系统不进行网络通信，不占用网络带宽。系统不使用数据库，不占用数据库存储空间。构建、测试和覆盖率报告产生的中间文件应可通过清理命令删除。


<!-- source-page: 43 -->

### 5.5 容量

系统为单用户桌面应用，不支持并发用户。本版本不对表达式长度设置业务上限；验收测试表达式长度不超过 255 个字符。绘图采样点数受 x 范围影响。极端范围可能生成大量点，本版本不以极端范围作为性能验收场景。系统默认保存最近 100 条计算历史记录；超过上限时，系统应按时间顺序移除最早记录。历史记录默认容量为最近 100 条，系统应在超过容量时自动删除最早记录。图像导出文件大小由绘图内容和导出格式决定，本版本不对导出文件数量设置系统级上限。

## 6 产品质量需求

### 6.1 可靠性

系统应在常规输入、计算和绘图过程中保持稳定，不因普通用户操作崩溃。系统应通过界面输入规则防止大多数非法表达式进入计算流程。系统应将 NAN 和 INF 结果转换为 calculation error 提示。核心计算模块应通过单元测试覆盖基础运算、变量运算、函数运算、科学计数法和混合表达式。模型层输入前置条件为表达式已通过界面层合法性校验；系统不保证对绕过界面层提交的任意非法字符串进行完整处理。历史记录写入失败时，不得影响本次计算结果显示。图像导出失败时，不得导致绘图窗口关闭或当前曲线丢失。

### 6.2 安全性

系统为本地桌面计算器，不处理账号、密码、身份认证和权限授权。系统无网络通信，不提供远程接口。系统无数据库访问；计算历史记录和导出图像仅保存在用户本地文件系统中。系统仅调用本地数学计算和 GUI 显示能力，不执行用户输入中的代码或脚本。

### 6.3 私密性

系统不收集、上传或保存用户个人信息。系统会在本地保存计算历史记录，记录内容可能包含用户输入的表达式和 x 值。系统不得上传历史记录，且应提供清空历史记录功能。系统关闭后，运行期内存中的表达式和计算结果由操作系统回收；已保存的历史记录仅保留在本地历史文件中，用户可通过清空历史功能删除。键盘输入应与按钮输入行为一致，用户可在键盘和按钮之间混合输入。历史记录应按时间倒序展示，最近一次计算记录位于列表前端。

### 6.4 可用性

系统通过按钮式 GUI 降低表达式输入复杂度。系统以 “0” 作为初始显示状态。系统提供 C 清空、退格、括号、变量、函数等常用按钮，并支持键盘数字、运算符和快捷键输入。错误结果以 calculation error 提示。绘图窗口显示当前绘制表达式；非法表达式显示 invalid input 。图像支持拖拽和缩放，便于用户观察函数趋势；用户可将当前图像导出为 PNG 或 PDF 文件。


<!-- source-page: 45 -->

### 6.5 可维护性

系统采用 MVC 架构，模型、视图和控制器职责清晰。表达式解析、计算和绘图坐标生成功能在模型层中相对独立。代码命名空间和目录结构应保持一致性。构建脚本应支持格式检查、测试、覆盖率报告、文档和打包等维护目标。

### 6.6 可移植性

系统使用 C++17 和 Qt ，具备跨平台构建基础。系统有分别适配 Windows 、 Linux 、 macOS 系统的安装脚本， CMake 配置保留不同桌面平台 GUI 应用构建能力。

## 8 软件开发约束性要求

### 8.1 软件设计约束

#### 8.1.1 技术平台约束

系统必须使用 C++17 标准开发。系统 GUI 必须基于 Qt Widgets 。系统必须保持 MVC 架构：视图层不直接实现核心数学算法，模型层不依赖 Qt UI 。系统计算模块必须能够脱离 GUI 进行单元测试。

#### 8.1.2 编程语言与框架约束

代码风格遵循 Google C++ style ，并通过 clang-format 检查。核心类应位于统一命名空间内。构建系统应保留 CMakeLists.txt 和 Makefile 。界面层可使用 Qt Designer .ui 文件维护布局。

#### 8.1.3 接口与协议约束

视图层与模型层之间通过控制器交互。计算接口接收表达式字符串和 x 值，返回数值结果。绘图接口接收表达式和 x 范围，返回 x/y 坐标序列。绘图模块返回标准容器数据，由界面层转换为绘图组件可展示的数据格式。

#### 8.1.4 数据与存储约束

本版本不使用数据库；计算历史记录和图像导出文件使用本地文件系统保存。除计算历史记录和用户导出的图像文件外，其他运行期数据仅保存在内存中。历史记录文件应采用可解析的本地文本格式或结构化格式保存；系统应提供清空历史记录的清理机制。

#### 8.1.5 部署与运维约束

构建过程应能生成 SmartCalc 可执行程序或应用包。发布归档应包含运行所需的源代码、构建脚本和相关资源。清理命令应删除测试、覆盖率、临时构建和打包中间文件。

### 8.3 验收要求

验收测试应以一级缺陷和二级缺陷发生率作为主要质量判定依据，并结合系统构建、核心功能、错误处理、界面交互、历史记录和图像导出等功能验证结果进行综合评定。一级缺陷指导致系统无法构建、无法启动、核心计算功能不可用、主要功能流程中断、程序崩溃、数据丢失或验收无法继续进行的严重缺陷。一级缺陷包括但不限于以下情况：

1. 系统无法在指定 Qt/C++17 环境下成功构建或生成可执行程序。

2. 主窗口无法正常启动、主要控件缺失、界面严重错乱导致用户无法完成基本操作。

3. 基础表达式计算功能不可用，例如无法正确计算 3+5=8、 20/4=5 等核心用例。

4. 括号、一元正负号、变量 x 、三角函数、对数、平方根、幂、科学计数法等核心计算能力存在普遍性错误。

5. 除零、负数开方、取模零、数值越界等异常场景导致程序崩溃或无响应。

6. 绘图窗口无法打开，或在合法表达式和合法范围下无法生成函数图像。

7. 键盘输入、历史记录、图像导出等新增功能存在导致主流程不可继续执行的严重问题。

8. 单元测试无法执行，或核心计算用例存在大面积失败。

9. 发布归档无法生成，导致项目无法完成验收交付。一级缺陷发生率按下式计算：

一级缺陷发生率 = 一级缺陷数量 / 已执行验收测试项总数 × 100% 系统验收通过时，一级缺陷发生率必须为 0% 。若发现任意一级缺陷，本轮验收判定为不通过，项目组应完成修复后重新提交验收。二级缺陷指不阻断系统主要功能使用，但会影响用户体验、功能完整性、结果展示、异常提示、边界处理或交付质量的一般缺陷。二级缺陷包括但不限于以下情况：

1. 主窗口能够使用，但部分控件显示不够规范、布局存在轻微重叠或提示信息不清晰。

2. 个别非核心表达式、边界输入或格式化显示结果存在偏差，但不影响基础计算主流程。

3. 错误输入能够被处理，但提示信息不够明确或与预期文本不完全一致。

4. 图像窗口能够绘制函数曲线，但拖拽、缩放、范围显示或刷新体验存在轻微问题。


<!-- source-page: 49 -->

5. 键盘输入大部分可用，但个别快捷键或非法按键处理不完整。

6. 历史记录能够保存和查看，但排序、显示字段、清空后的空状态提示等存在轻微问题。

7. 图像能够导出为 PNG 或 PDF ，但成功/ 失败提示、默认文件名、格式选择等体验存在不足。

8. 格式检查、文档、归档文件等交付项存在轻微规范问题，但不影响系统运行和验收判断。二级缺陷发生率按下式计算：

二级缺陷发生率 = 二级缺陷数量 / 已执行验收测试项总数 × 100% 系统验收通过时，二级缺陷发生率应不高于 10% 。若二级缺陷发生率高于 10% ，但不存在一级缺陷，可判定为有条件通过，项目组应在规定时间内完成整改；若二级缺陷集中出现在同一核心模块并影响功能完整性，验收人员可要求重新验收。验收结论按以下规则判定：

1. 通过：一级缺陷发生率为 0% ，二级缺陷发生率不高于 10% ，且构建、核心计算、变量计算、错误处理、绘图、键盘输入、历史记录、图像导出和发布归档等主要验收项均已完成。

2. 有条件通过：一级缺陷发生率为 0% ，二级缺陷发生率高于 10% 但不高于 20% ，系统主要功能可用，缺陷不阻断课程演示和基本交付。

3. 不通过：存在任意一级缺陷，或二级缺陷发生率高于 20% ，或关键交付物缺失，或系统无法完成主要验收流程。

### 8.4 用户界面要求

#### 8.4.1 通用要求

主窗口应固定显示计算器按钮、显示区、 x 输入框、历史记录入口和必要的键盘输入提示。显示区初始值为 0 。按钮应使用数学符号和函数名标识。非法输入应通过输入规则限制，避免弹出复杂对话框。错误结果应在显示区显示 calculation error 。清空按钮 C 应立即恢复初始状态。退格按钮应删除最近一次输入的完整 token 或最近输入字符。主窗口和图像窗口尺寸固定。

#### 8.4.2 主计算界面要求

提供数字按钮 0~9 。提供 + 、 - 、×、÷、 mod 、 xʸ、√、 e 、.、括号按钮。提供 sin 、 cos 、 tan 、 asin 、 acos 、 atan 、 ln 、 log 函数按钮。提供变量 x 按钮和 x 值输入框。 x 值输入框限制为合法数值，范围约为 ±100000000000 ，最多 6 位小数。点击 = 后，若表达式合法，则显示计算结果；若结果无效，则显示 calculation error 。若计算结果过长，应使用科学计数法显示。


<!-- source-page: 50 -->

#### 8.4.3 图像界面要求

图像窗口应显示待绘制表达式。应提供 x_min 、 x_max 、 y_min 、 y_max 设置控件。默认 x 范围为 -10 到 10 ，默认 y 范围为 -5 到 5 。坐标范围控件允许 -1000000 到 1000000 。图像区域应使用绘图组件绘制曲线。图像应支持拖拽、缩放和导出。非法表达式应显示 invalid input 并清除旧图像；导出前若当前无有效图像，系统应提示导出失败或拒绝导出。

#### 8.4.4 历史记录界面要求

主窗口或独立历史区域应提供历史记录入口。历史记录应展示表达式、 x 值、计算结果和计算时间。历史记录默认按时间倒序排列。用户选择历史记录后，系统应能将表达式和 x 值载入主计算界面。历史记录区域应提供清空历史功能。

#### 8.4.5 键盘输入界面要求

主窗口处于激活状态时，应响应数字键、运算符键、括号键、小数点、变量 x 和 e 。 Enter 或 Return 应触发计算。 Backspace 应执行退格删除。 Esc 或 Delete 应清空当前表达式。非法键盘输入不得改变当前表达式。

#### 8.4.6 图像导出界面要求

图像窗口应提供导出按钮或导出菜单项。系统应允许用户选择 PNG 或 PDF 格式。系统应允许用户选择本地保存路径。导出成功后应给出成功提示；导出失败时应给出失败原因或通用失败提示。
